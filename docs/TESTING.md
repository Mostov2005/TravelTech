
# Тестирование микросервисов TravelTech

## 1. Назначение

Тестирование используется для проверки корректности работы микросервисов TravelTech и их отдельных компонентов.

В проекте используются два вида тестирования:

- **Unit-тестирование** — проверка отдельных компонентов, в первую очередь бизнес-логики сервисного слоя. Для изоляции тестируемой логики используются mock-объекты (`MagicMock`), заменяющие репозитории и другие зависимости.
- **Интеграционное тестирование** — проверка взаимодействия компонентов через API с использованием тестовой базы данных.

Для запуска тестов используется `pytest`.

## 4. Интеграционное тестирование

Интеграционные тесты проверяют взаимодействие компонентов микросервиса через HTTP API с использованием FastAPI TestClient и базы данных PostgreSQL.

На текущий момент интеграционные тесты реализованы для Trip Service.

Файл с тестами:

```text
services/trip_service/tests/test_integration.py
```

Проверяются следующие сценарии:

1. **Жизненный цикл поездки** — создание поездки, получение информации о ней, удаление и проверка ответа 404 при повторном запросе.
2. **Работа с сегментами маршрута** — создание поездки, добавление сегмента маршрута, получение списка сегментов и удаление поездки.
3. **Работа с бронированиями** — создание поездки, добавление бронирования, получение информации о бронировании и его удаление.

Количество интеграционных тестов: **3**.

Команда запуска:

```bash
python -m pytest services/trip_service/tests/test_integration.py -v
```

В дальнейшем планируется добавить интеграционные тесты для остальных четырёх микросервисов.

## 5. Запуск всех тестов проекта

Для последовательного запуска unit- и интеграционных тестов всех микросервисов используется скрипт `run_tests.py`, расположенный в корне проекта.

Команда запуска:

```bash
python run_tests.py
```

Скрипт последовательно запускает тесты каждого микросервиса и завершает выполнение с сообщением об ошибке, если какой-либо набор тестов не пройден.
