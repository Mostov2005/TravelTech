# Тестирование микросервисов TravelTech

## 1. Назначение

Тестирование используется для проверки корректности работы микросервисов TravelTech и их отдельных компонентов.

В проекте используются два вида тестирования:

- **Unit-тестирование** — проверка отдельных компонентов, в первую очередь бизнес-логики сервисного слоя. Для изоляции тестируемой логики используются mock-объекты (`MagicMock`), заменяющие репозитории и другие зависимости.
- **Интеграционное тестирование** — проверка взаимодействия компонентов через API с использованием тестовой базы данных.

Для запуска тестов используется `pytest`.

## 4. Интеграционное тестирование

Интеграционные тесты проверяют взаимодействие компонентов микросервиса через HTTP API с использованием FastAPI TestClient и базы данных PostgreSQL.

На текущий момент интеграционные тесты реализованы для Trip Service.

Файл с тестами:

```text
services/trip_service/tests/test_integration.py
```

Проверяются следующие сценарии:

1. **Жизненный цикл путешествия** — создание путешествия, получение информации о нём, удаление и проверка ответа 404 при повторном запросе.
2. **Работа с сегментами маршрута** — создание путешествия, добавление сегмента маршрута, получение списка сегментов и удаление путешествия.
3. **Работа с бронированиями** — создание путешествия, добавление бронирования, получение информации о бронировании и его удаление.

Количество интеграционных тестов: **3**.

Команда запуска:

```bash
python -m pytest services/trip_service/tests/test_integration.py -v
```

## 5. Запуск всех тестов проекта

Для последовательного запуска тестов всех микросервисов используется скрипт `run_tests.py`, расположенный в корне проекта.

Команда запуска:

```bash
python run_tests.py
```

Также можно запустить тесты напрямую:

```bash
pytest services/ -v
```

Для проверки количества обнаруженных тестов используется команда:

```bash
pytest services/ --collect-only -q
```

## 6. Непрерывная интеграция

Автоматический запуск тестов настроен с помощью GitHub Actions.

Конфигурация находится в файле:

```text
.github/workflows/tests.yml
```

При отправке изменений в ветку `master` или создании Pull Request автоматически запускаются тесты микросервисов в CI-окружении.

## 7. Итоги

Тестирование позволяет проверять отдельную бизнес-логику микросервисов и взаимодействие компонентов через API. Автоматический запуск тестов также выполняется в рамках CI с использованием GitHub Actions.
