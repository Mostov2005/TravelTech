# Бизнес-процессы системы TravelTech

## 1. Управление пользователями

**Участник:** пользователь, администратор.

**Описание:** процесс регистрации пользователей, аутентификации и управления учётными записями.

**Последовательность действий:**
1. Пользователь отправляет данные для регистрации.
2. Система проверяет корректность данных.
3. Система создаёт учётную запись.
4. Пользователь выполняет вход в систему.
5. Система проверяет учётные данные и выдаёт JWT-токен.
6. При необходимости пользователь обновляет токен или выходит из системы.

**Результат:** пользователь получает доступ к функциям системы в соответствии со своими правами.

## 2. Управление путешествиями

**Участник:** пользователь.

**Описание:** процесс создания и управления отдельными путешествиями.

**Последовательность действий:**
1. Пользователь создаёт новое путешествие.
2. Указывает название, даты и основную информацию.
3. Система сохраняет путешествие.
4. Пользователь может просматривать, редактировать или завершать путешествие.

**Результат:** в системе хранится путешествие пользователя с актуальной информацией.

## 3. Управление маршрутами

**Участник:** пользователь.

**Описание:** процесс формирования маршрута путешествия, состоящего из одного или нескольких этапов.

**Последовательность действий:**
1. Пользователь открывает созданное путешествие.
2. Добавляет пункты маршрута.
3. Указывает аэропорты, даты и время перемещения.
4. Система проверяет корректность маршрута.
5. Система сохраняет изменения.
6. Пользователь может изменять последовательность и состав этапов маршрута.

**Результат:** путешествие содержит актуальный маршрут.

## 4. Управление бронированиями

**Участник:** пользователь.

**Описание:** процесс добавления и управления информацией о бронированиях, связанных с путешествием.

**Последовательность действий:**
1. Пользователь добавляет информацию о бронировании авиарейса.
2. Указывает номер рейса, дату, данные бронирования и пассажиров.
3. Система проверяет корректность введённых данных.
4. Бронирование связывается с соответствующим путешествием.
5. Пользователь может просматривать информацию о бронировании и изменять её.

**Результат:** в системе хранится информация о бронированиях пользователя.

Примечание: на первом этапе TravelTech хранит информацию о бронированиях, но не выполняет реальные платежи и не покупает авиабилеты.

## 5. Работа с авиарейсами

**Участник:** внутренние сервисы системы, внешние источники информации.

**Описание:** получение и предоставление информации об авиарейсах и аэропортах.

**Последовательность действий:**
1. Система получает информацию о рейсах из внешнего источника.
2. Проверяет и обрабатывает полученные данные.
3. Сохраняет информацию о рейсах и аэропортах.
4. Предоставляет другим сервисам возможность получать сведения о рейсах.

**Результат:** система располагает актуальной информацией о рейсах и аэропортах в пределах доступности внешнего источника.

## 6. Мониторинг авиарейсов

**Участник:** внутренние сервисы системы, внешние источники информации.

**Описание:** автоматическое отслеживание состояния авиарейсов, добавленных в путешествия пользователей.

**Последовательность действий:**
1. Система получает список рейсов, которые необходимо отслеживать.
2. Периодически запрашивает актуальную информацию из внешнего источника.
3. Сравнивает новые данные с предыдущими.
4. Выявляет изменения статусов и расписания.
5. При обнаружении значимого изменения формирует событие.

**Результат:** система отслеживает изменения состояния рейсов и передаёт информацию о них заинтересованным сервисам.

## 7. Обработка нарушений авиасообщения

**Участник:** внутренние сервисы системы.

**Описание:** обработка отмен, существенных задержек и других изменений, которые могут повлиять на путешествие пользователя.

**Последовательность действий:**
1. Система получает информацию об изменении состояния рейса.
2. Определяет, какие путешествия затрагивает это изменение.
3. Создаёт обращение о возникшей проблеме.
4. Получает информацию о соответствующем путешествии и бронировании.
5. Оценивает влияние изменения на дальнейший маршрут.

**Результат:** зарегистрирована проблема, требующая внимания пользователя или дальнейшей обработки системой.

## 8. Корректировка путешествий

**Участник:** пользователь, внутренние сервисы системы.

**Описание:** поиск альтернативных вариантов перелёта и подготовка предложений по изменению маршрута.

**Последовательность действий:**
1. Система получает информацию о проблемном рейсе и связанном путешествии.
2. Определяет параметры поиска альтернатив.
3. Запрашивает доступные варианты перелётов.
4. Формирует предложения по замене рейса.
5. Передаёт предложения пользователю.
6. Пользователь выбирает подходящий вариант.
7. Система обновляет маршрут и связанную с ним информацию о бронировании.

**Результат:** путешествие скорректировано после подтверждения пользователя.

Примечание: система формирует предложения, но не выполняет реальное перебронирование у авиакомпании.

## 9. Уведомления

**Участник:** внутренние сервисы системы, пользователь.

**Описание:** информирование пользователей о важных событиях, связанных с их путешествиями.

**Последовательность действий:**
1. Система получает событие, требующее уведомления.
2. Определяет получателя и содержание сообщения.
3. Формирует уведомление.
4. Отправляет его пользователю через доступный канал.
5. Сохраняет информацию об отправке.

**Результат:** пользователь получает информацию об изменениях в своём путешествии и предложенных вариантах действий.
