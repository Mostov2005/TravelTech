# TravelTech — система управления путешествиями

## 1. Назначение системы

TravelTech — информационная система, предназначенная для планирования и управления путешествиями пользователей, хранения
информации об авиарейсах и мониторинга их состояния.

Система позволяет пользователям создавать путешествия, формировать маршруты, добавлять информацию о бронированиях и
работать с данными об авиарейсах и аэропортах.

Для отслеживания состояния рейсов предусмотрен отдельный микросервис, который хранит текущие статусы и историю их
изменений.

Также система поддерживает обработку нарушений авиасообщения: регистрацию проблем, связанных с рейсами, и подготовку
предложений по восстановлению маршрута. Координация этого процесса выполняется с использованием паттерна Saga
Orchestration.

## 2. Основные задачи системы

1. Регистрация пользователей и управление учётными записями.
2. Аутентификация пользователей с использованием JWT.
3. Создание и управление путешествиями.
4. Формирование маршрутов путешествий.
5. Хранение информации о бронированиях.
6. Хранение и предоставление информации об авиарейсах и аэропортах.
7. Создание записей мониторинга авиарейсов.
8. Хранение текущих статусов и истории их изменений.
9. Регистрация случаев нарушения авиасообщения.
10. Формирование предложений по восстановлению маршрута.
11. Координация распределённых операций между микросервисами.

## 3. Пользователи системы

- **Путешественник** — регистрируется в системе, создаёт путешествия, управляет маршрутами и бронированиями,
  просматривает информацию о рейсах.
- **Пользователь с ролью администратора** — роль предусмотрена в модели пользователей Identity Service. Отдельные
  административные функции в текущей реализации не разработаны.

## 4. Основной бизнес-сценарий

Пользователь регистрируется в системе и проходит аутентификацию. После этого он создаёт путешествие, добавляет сегменты
маршрута и сохраняет информацию о бронированиях.

Данные о путешествиях и бронированиях хранятся в Trip Service. Информация об аэропортах и авиарейсах хранится отдельно в
Flight Service.

Для работы с состояниями рейсов используется Flight Monitoring Service. Он хранит записи мониторинга и историю изменения
статусов.

Если возникает нарушение авиасообщения, Recovery Service позволяет зарегистрировать соответствующий случай и
сформировать предложение по использованию альтернативного рейса. При выполнении операций изменения путешествия сервис
координирует взаимодействие с другими микросервисами с помощью Saga Orchestration.

Пользователь может работать с информацией о путешествии и его маршруте через соответствующие функции системы.

## 5. Ограничения текущей реализации

- Система не выполняет покупку авиабилетов и реальные платежи.
- Интеграция с внешними поставщиками данных об авиарейсах не реализована.
- Автоматическое получение данных о задержках и отменах рейсов не реализовано.
- Автоматическая отправка уведомлений пользователям не реализована.
- Предложения по восстановлению маршрута хранятся в системе, но реальное перебронирование у авиакомпаний не выполняется.
