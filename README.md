# TravelTech

**TravelTech** — микросервисная система для управления путешествиями, хранения информации об авиарейсах и мониторинга их состояния.

## 1. Назначение проекта

Система предназначена для планирования путешествий, управления маршрутами и бронированиями, а также работы с информацией об авиарейсах.

TravelTech позволяет регистрировать пользователей, создавать путешествия, формировать маршруты и хранить информацию о бронированиях.

Для работы с состояниями авиарейсов предусмотрен отдельный микросервис мониторинга. Также реализован механизм регистрации нарушений авиасообщения и координации операций по восстановлению путешествий.

## 2. Основные возможности

- Регистрация и аутентификация пользователей.
- Управление учётными записями и ролями.
- Создание, просмотр, редактирование и удаление путешествий.
- Формирование маршрутов и управление их сегментами.
- Управление информацией о бронированиях.
- Хранение информации об авиарейсах и аэропортах.
- Создание записей мониторинга авиарейсов.
- Хранение текущих статусов и истории их изменений.
- Регистрация случаев нарушения авиасообщения.
- Формирование предложений по восстановлению маршрута.
- Асинхронный обмен событиями между микросервисами.

## 3. Архитектура

Проект построен на основе микросервисной архитектуры с применением Domain-Driven Design (DDD) и принципов Clean Architecture.

Система разделена на пять ограниченных контекстов (Bounded Contexts), каждый из которых реализован отдельным микросервисом.

| Микросервис | Ответственность | Порт |
|---|---|---:|
| Identity Service | Пользователи, роли и аутентификация | 8004 |
| Trip Service | Путешествия, маршруты и бронирования | 8000 |
| Flight Service | Авиарейсы и аэропорты | 8002 |
| Flight Monitoring Service | Мониторинг рейсов и история статусов | 8003 |
| Recovery Service | Обработка нарушений и восстановление путешествий | 8001 |

Каждый микросервис использует отдельную базу данных PostgreSQL.

## 4. Технологический стек

- **Python 3.11** — основной язык разработки.
- **FastAPI** — реализация REST API.
- **PostgreSQL** — хранение данных микросервисов.
- **SQLAlchemy** — взаимодействие с базами данных.
- **Redis** — кэширование данных.
- **RabbitMQ** — асинхронное взаимодействие между сервисами.
- **gRPC** — синхронное взаимодействие между микросервисами.
- **JWT** — аутентификация и защита API.
- **Docker и Docker Compose** — контейнеризация и запуск системы.
- **Pytest** — модульное и интеграционное тестирование.
- **GitHub Actions** — автоматический запуск тестов.

## 5. Реализованные архитектурные механизмы

В проекте реализованы следующие механизмы:

- **Saga Orchestration** — координация распределённых операций через Recovery Service с использованием компенсирующих действий.
- **Transactional Outbox** — сохранение событий в одной транзакции с бизнес-данными и последующая публикация через RabbitMQ.
- **Redis Cache** — кэширование данных для уменьшения количества обращений к PostgreSQL.
- **gRPC** — синхронное взаимодействие Flight Service и Flight Monitoring Service.
- **JWT Authentication** — единый механизм аутентификации через Identity Service.
- **Database per Service** — отдельная база данных PostgreSQL для каждого микросервиса.

## 7. Запуск проекта

Для запуска необходимы Docker и Docker Compose.

**Клонирование репозитория:**

```bash
git clone https://github.com/Mostov2005/TravelTech.git
cd TravelTech
```

**Запуск всех сервисов:**

```bash
docker compose up --build -d
```

**Проверка состояния контейнеров:**

```bash
docker compose ps
```

**Остановка системы:**

```bash
docker compose down
```

## 9. Тестирование

Для тестирования используется Pytest.

**Запуск всех тестов:**

```bash
pytest services/ -v
```

В проекте реализованы модульные и интеграционные тесты для микросервисов.

**Результат последнего успешного запуска: 55 тестов пройдены.**

## 10. Непрерывная интеграция

Для автоматизации тестирования используется GitHub Actions.

Конфигурация находится в файле:

```text
.github/workflows/tests.yml
```

При отправке изменений в ветку `master` или создании Pull Request автоматически запускаются тесты микросервисов.

## 11. Ограничения текущей реализации

- Интеграция с внешними поставщиками данных об авиарейсах не реализована.
- Автоматическое получение информации об отменах и задержках рейсов не реализовано.
- Автоматическая отправка уведомлений пользователям не реализована.
- Система не выполняет реальные платежи и покупку авиабилетов.
- Предложения по восстановлению маршрута не являются реальным перебронированием у авиакомпании.
